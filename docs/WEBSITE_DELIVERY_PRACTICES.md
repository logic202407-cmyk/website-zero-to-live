# 可复用的网站交付经验

个人网站的默认目标是让读者理解用户的真实经历、代表作品和贡献，并能采取联系等下一步动作。先使用轻量路线交付可访问的首版；复杂业务能力按需要增加。

## 从用户任务开始

明确谁在什么场景完成什么动作，以及最终拿到什么结果。优先实现一条真实旅程，而不是按页面数量衡量进度。展示站、会员系统、商城与重计算应用的复杂度不同，先选最小足够架构。

## 先定边界和契约

先明确输入、输出、权限、存储范围、状态转换和重复提交行为。缺失值、空值与零值不可混用。客户端改善交互，服务端重新校验；模型输出不能充当事实、权限或付款凭证。

## 按纵向切片开发

每轮完成界面、校验、业务、存储、反馈和针对性验证。复杂业务将领域逻辑、Repository和外部供应商适配器分开；简单静态站不引入无用分层。已有项目先检查实现，不重建已有能力。

## 将界面设计落到真实操作

先整理内容层级和用户动作，再确定字体、色彩、间距与组件。覆盖加载、空、成功、失败和无权限状态。桌面和手机均检查真实浏览器，兼顾键盘、焦点、长内容和减少动画偏好。截图能证明画面，不能单独证明功能可用。

## 区分数据保存的层级

浏览器记录、进程内存与云端数据库具有不同生命周期。明确刷新、浏览器清理、跨设备和实例重启后的行为。账号系统用真实用户验证对象所有权和隔离，管理员凭据测试不能替代普通用户权限测试。

## 尽早验证部署运行时

框架在本机Node环境成功，不代表边缘运行时或容器部署成功。尽早以最小页面和必要服务端请求验证选定平台，再扩展业务。版本、插件、配额、DNS目标和价格以当前官方资料为准。

## 将域名购买和网站部署分开理解

注册商管理域名所有权与续费，DNS提供解析，托管平台运行应用，证书提供HTTPS。购买前检查准确拼写、年限、总价、续费及账号归属。修改DNS前保留已有邮箱与子域记录，再配置正式域名、证书和回调URL。

## 发布必须对应可核验的版本

验证流水线和发布流水线分开。发布绑定精确源码SHA或产物digest，核对实际checkout与平台版本，不能只看分支名和流水线绿灯。公开构建变量与运行时secret分开管理；数据库迁移与应用发布分别记录。

## 保存失败证据并准备恢复

将本地测试、模拟服务、真实外部请求、公网交互和真实用户效果分开报告。余额不足、登录失败和DNS异常不应被隐藏为成功。回滚方案覆盖应用版本、数据库兼容、secret和DNS缓存，不能只写“回退代码”。

## 交接完整的维护能力

交付代码位置、运行方法、版本证据、资源归属、配置存放位置、续费负责人、备份恢复、监控告警和具体待办。能够后续维护和恢复，才是完整交付的一部分。
